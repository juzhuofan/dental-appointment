# 每周自动排班与请假管理验证记录

日期：2026-10-15，诊所时区：Asia/Shanghai。

## 已实现

- XXL-JOB core / 独立调度中心均固定 3.5.0；执行器默认关闭，启用前验证配置，GLUE 关闭。
- 每周日 00:00，Cron 为 `0 0 0 ? * SUN`，生成接下来周一至周日；默认依据本次触发时间确定调度周期，周一补偿不会误生成再下一周。
- 复制前一周正式排班的星期、时段、号源及预约截止分钟数，生成 `PUBLISHED`、`bookedSlots=0`。无本周来源时沿用最近正常周；无任何来源则报告医生编号，要求先手工维护首周。
- 已批准请假跳过整段相交排班；请假停诊来源与 LEAVE 台账保留名义时段，下一周可恢复。草稿、普通手工停诊、删除记录不直接作为正式来源。
- 独立生成台账、唯一键及医生事务锁避免重跑重复，保留手工排班和已有占号；删除已生成排班后重跑也不会复活。每位医生独立事务，失败可补跑，已成功部分不重复。
- 医生申请/撤回本人待审批请假；管理员批准/拒绝。批准影响活动预约时先返回专用 409，明确确认后同事务停诊、取消预约并释放号源。预期的影响确认不会另弹错误提示。
- 手工新增、修改、发布排班也检查已批准请假。审批与生成固定使用科室、医生、排班、预约锁顺序；请假查询使用当前读，避免旧快照漏读。
- 独立 Compose、官方同版 DDL、初始凭据校验及预置本项目任务。初始化任务保持停止，字段已填好，首次部署完成连通验收后即可启动。

## 复测入口与日志

- 后端：在 `backend` 执行 Maven `package -Dai.live=false -Dai.database=false`；本机使用 Java 17、低内存 SerialGC 和预加载 Byte Buddy agent，避免 Windows 自附加进程内存失败。
- 数据库：项目根目录执行 `scripts/Test-WeeklyScheduleDatabase.ps1`，可通过参数指定 MySQL、Java、Maven 和 agent 路径。
- 前端行为：`npm run test:unit`。
- 页面：`npm run test:regression-ui`。本机设置 `RAYON_NUM_THREADS=1`、`NODE_OPTIONS=--max-old-space-size=512` 限制构建峰值；API 全部模拟，不调用微信、付费模型或业务库。
- 主要日志：`.local/weekly-backend-tests.log`、`.local/weekly-database-tests.log`、`.local/weekly-client-tests.log`、`.local/weekly-ui-tests.log`。

本机 Edge 复用浏览器时曾拒绝加载 H5 静态模块，trace 明确记录 `ERR_INSUFFICIENT_RESOURCES`。AI 页面测试改为每个用例独立浏览器，首次静态资源耗尽仅允许一次真正刷新文档；业务断言和 API 失败不重试。最终整组 19 项通过。
