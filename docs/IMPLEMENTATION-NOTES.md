# 初版实现约定

本项目按原设计文档搭建，并采用用户确认的本机 Java 17、MySQL 8.0.45、Redis 3.2.100、Node.js 24.18.0。新增约定如下：

1. 小程序启动只检查已有 token，未登录显示登录选项；点击微信登录后，由后端 code2Session 验证 OpenID 并注册或恢复 PATIENT 账号。头像不是登录前置条件，个人中心可独立选择并上传 OSS。微信响应支持 text/plain JSON，避免转换器异常误报网络失败。当前个人主体不启用微信手机号能力，联系方式由用户在就诊资料中填写，手机号登录入口暂未开放。
2. Redis 3.2.100 使用本机 Windows 服务，不放入 Linux Docker Compose。仅缓存公开诊所信息；Redis 故障时查询降级，预约事实和身份撤销保存在 MySQL。
3. 管理端与 uni-app 使用各自兼容的构建依赖，分别固定锁文件，不能将管理端 Vite 版本直接用于 uni-app。
4. 预约创建为 PENDING，管理员确认后进入 CONFIRMED，医生或管理员可完成/登记爽约。booked_slots 表示 PENDING/CONFIRMED 活动预约数，终态只释放一次。已过开始时间的排班不接受新预约，因此已完成就诊释放活动占用不会重新出售过期时段。
5. 并发预约通过数据库事务和唯一活动预约键保护；更新采用固定锁顺序（排班→预约）。患者取消遵循截止时间，管理员停诊/删除排班应在事务中取消活动预约并释放号源。
6. 排班始终不允许变更所属医生，需要重新创建；已有活动预约的排班不允许变更时间。新增排班检查时间交叉。科室、医生和账号删除/停用需取消关联活动预约，并保留历史快照。
7. 所有业务及支撑表包含 deleted、created_at、updated_at；所有业务删除为逻辑删除，普通查询过滤 deleted=0。有效账号唯一值通过生成列/唯一索引维护；关系记录重新绑定时恢复旧行。Flyway 自身版本表由框架维护。
8. 所有业务 JSON 请求体为 R<T>，参数放 data；所有业务响应、参数错误、认证失败、权限错误均使用 R。Query、Path、Header 按 HTTP 语义传递。R.data 的业务 DTO 需非空及级联校验。
9. 按用户要求，后端连接、OSS 和微信配置使用 application.yml 静态值，AppSecret 与 OSS 凭证仅供后端使用，前端不包含凭证。工具环境仍可使用 .env.local；运行日志、模拟微信身份的独立数据库/OSS 测试产物放 .local 忽略目录。数据库头像 URL 不加密且不含签名，私有头像展示用另一个短期签名字段。
10. 本地仓库关联用户提供的 GitHub origin。初版交付以本机源码、编译产物和可运行服务为准；推送/发布另行按用户要求执行。
